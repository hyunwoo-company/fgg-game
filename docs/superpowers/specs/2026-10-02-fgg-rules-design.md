# FGG 사신수 게임 숫자·조합 규칙 — 설계

- 작성일: 2026-10-02
- 상태: 사용자 검토 대기
- 브랜치: `claude/nostalgic-gates-b3b411`

## 1. 배경과 목표

이 설계는 사용자와 확정한 FGG 사신수 게임의 숫자·조합·점수 규칙을 정리합니다. 핵심은 숫자 서열을 "2가 최강"으로 두는 것입니다.

사신수 테마, 타일 디자인, full 모드, 턴 타이머 같은 FGG 고유 요소는 유지합니다. 사신수 대응은 사용자 요청에 따라 **주작(해) > 청룡(달) > 현무(별) > 백호(구름)**으로 변경합니다. 내부 문양 키와 해 > 달 > 별 > 구름의 서열은 유지하고, 이름과 그림의 대응을 바꿉니다.

**최강 숫자는 game-logic의 단일 상수 `TOP_NUMBER`로 둡니다.** 현재 `main`에 반영된 타일 디자인(최강 숫자 타일에 특별 그림 사용)도 이 상수 하나로 연결합니다.

## 2. 확정 룰

모두 사용자가 대화에서 확정했습니다. 근거로 삼은 출처는 13절에 있습니다.

| # | 항목 | 확정 내용 |
|---|---|---|
| R1 | 숫자 서열 | `2 > 1 > 15 > 14 > … > 4 > 3`. 2가 최강, 3이 최약 |
| R2 | 문양 서열 | **주작(해, sun) > 청룡(달, moon) > 현무(별, star) > 백호(구름, cloud)**. `SUIT_RANK`는 유지하고 사신수 이름·그림 대응을 변경 |
| R3 | 선 | **매 라운드** 백호 3(`cloud-3`, 가장 약한 타일) 보유자가 선. 첫 턴에 백호 3을 반드시 낼 필요는 없음 |
| R4 | 라운드 중 새 선 | 나머지 전원이 패스하면 마지막에 낸 사람이 새 선(기존과 같음) |
| R5 | 스트레이트 구성 | 문양 무관, 연속 숫자 5장. 아래 세 형태만 1·2가 포함된 스트레이트로 인정 |
| R5-a | | `1-2-3-4-5` |
| R5-b | | `2-3-4-5-6` |
| R5-c | | `(최고숫자-3)…(최고숫자)-1`. 1이 인원별 최고 숫자 바로 뒤에 붙는 형태. 3인 `6-7-8-9-1` / 4인 `10-11-12-13-1` / 5인·full `12-13-14-15-1` |

| R7 | 스트레이트 동률 | 서열이 같으면 **가장 강한 타일의 문양**으로 비교. R5-a·R5-b는 2의 문양, R5-c는 1의 문양, 일반은 가장 높은 숫자의 문양 |
| R8 | 스트레이트 플러시 | 서열과 동률 규칙 모두 R6·R7과 같음. 최강은 주작 `1-2-3-4-5` |
| R9 | 나머지 조합 | 싱글·페어·트리플은 가장 강한 타일 기준, 풀하우스는 트리플 숫자, 포카드는 4장 숫자, 플러시는 가장 강한 타일(숫자 → 문양)로 비교. 기존과 같고 서열만 R1로 바뀜 |
| R10 | 낼 수 있는 개수 | 1·2·3·5장. 4장 불가(기존과 같음) |
| R11 | 페널티 | 라운드 종료 시 숫자 **2**를 n장 들고 있으면 남은 패 × 2^n (1장 ×2, 2장 ×4, 3장 ×8) |
| R12 | 모드 | 기본 모드는 인원별 타일 범위 사용(3인 1~9·12장 / 4인 1~13·13장 / 5인 1~15·12장). FGG 확장 **full 모드는 유지** |

## 4. 구현 방식

강도값 구조(`TileCombination.strength: number`)는 그대로 두고, 상수와 스트레이트 강도 계산만 바꿉니다. 서버와 웹에서 이 값을 쓰는 코드는 수정할 필요가 없습니다.

검토했지만 쓰지 않은 대안은 두 가지입니다.
- 포커처럼 두 번째로 높은 숫자까지 비교하는 방식: `strength` 타입이 바뀌어 모든 앱에 영향이 감
- 여러 규칙 세트 사이의 전환 구조: 요구사항이 아님

## 5. game-logic 설계 (`packages/game-logic/src`)

### 5.1 `constants.ts`
```ts
// FGG 숫자 서열: 2가 최강(14), 3이 최약(0)
export const NUMBER_RANK: Record<TileNumber, number> = {
  3: 0, 4: 1, 5: 2, 6: 3, 7: 4, 8: 5, 9: 6,
  10: 7, 11: 8, 12: 9, 13: 10, 14: 11, 15: 12,
  1: 13, 2: 14,
};

/** 최강 숫자 — 페널티 대상, 타일 특별 디자인 대상 */
export const TOP_NUMBER: TileNumber = 2;

/** 매 라운드 이 타일 보유자가 선 */
export const FIRST_PLAYER_TILE: { readonly suit: Suit; readonly number: TileNumber } = { suit: 'cloud', number: 3 };

/** 사신수 대응 — 해 > 달 > 별 > 구름의 내부 서열은 유지 */
export const SUIT_LABEL: Record<Suit, string> = {
  sun: '주작',
  moon: '청룡',
  star: '현무',
  cloud: '백호',
};
```
- `SUIT_RANK`, `COMBINATION_RANK`, `GAME_CONFIG`, `GAME_CONFIG_FULL`은 변경하지 않습니다.
- `SUIT_LABEL`은 위 대응으로 바꿉니다. `FIRST_PLAYER_TILE`의 `cloud-3`은 새 대응에서 **백호 3**입니다. 타일 ID와 Socket.io의 문양 키는 변경하지 않습니다.
- 서열을 설명하는 주석은 확정 규칙(R1)에 맞춥니다.

### 5.2 `deck.ts`
- `findFirstPlayer`가 `FIRST_PLAYER_TILE`과 같은 타일을 가진 사람을 찾도록 바꿉니다.
- 아무도 없으면 0을 반환하는 기존 fallback은 유지합니다. 기본 모드 3인(1~9)에도 백호 3은 항상 포함되므로 정상 배분에서는 발생하지 않습니다.

### 5.3 `scorer.ts`
- 페널티 판정을 `t.number === 1`에서 `t.number === TOP_NUMBER`로 바꿉니다. 배율 공식 2^n은 유지합니다.

### 5.4 `validator.ts` — 스트레이트

**유효성 판정**: 인정하는 조합은 현재 코드와 **같습니다**. 현재 분기(1과 2가 모두 있으면 `1-2-3-4-5`만, 1만 있으면 ace high만, 둘 다 없거나 2만 있으면 숫자 연속)가 R5와 일치합니다. 분기 구조는 유지하고 주석만 FGG 기준으로 고칩니다.

**강도 계산(`straightStrength`)만 다시 씁니다.**

| 형태 | 서열값 `seq` | 문양 비교 대상 |
|---|---|---|
| `1-2-3-4-5` | 15 (`NUMBER_RANK[2] + 1`) | 2 |
| `2-3-4-5-6` | 14 (`NUMBER_RANK[2]`) | 2 |
| `…-최고숫자-1` | 13 (`NUMBER_RANK[1]`) | 1 |
| 일반 | `NUMBER_RANK[가장 높은 숫자]` (4~12) | 가장 높은 숫자 |

```
strength = seq * 10 + SUIT_RANK[문양 비교 대상 타일.suit]
```

- 문양 비교 대상 타일은 모든 경우에 `getStrongestTile(tiles)`의 결과와 같습니다. 구현은 `getStrongestTile`을 써도 됩니다.
- `straight`와 `straightflush`가 같은 함수를 씁니다.
- 일반 스트레이트의 최대 서열값은 12(15 top)로, ace high(13)보다 항상 작습니다. 3인 모드(9 top = 6)에서도 순서가 유지됩니다.

### 5.5 `index.ts`
- `constants`를 전부 export하므로 `TOP_NUMBER`, `FIRST_PLAYER_TILE`이 자동으로 노출됩니다. 확인만 합니다.

### 5.6 테스트 (`packages/game-logic/__tests__/`)
1이 최강이라는 전제의 기존 테스트("FGG:" 접두)는 R1~R11 기준으로 갱신합니다. 아래 케이스는 반드시 있어야 합니다.

- **서열**: 싱글 2 > 싱글 1 > 싱글 15. 싱글 3이 최약. 같은 숫자면 주작(sun) > 청룡(moon) > 현무(star) > 백호(cloud). `SUIT_LABEL`도 이 대응인지 확인
- **첫 선**: 백호 3(`cloud-3`) 보유자 인덱스를 반환. 백호 2(`cloud-2`)나 청룡 3(`moon-3`) 보유자는 선이 아님
- **페널티**: 2를 1·2·3장 보유하면 배율 ×2·×4·×8. 1을 보유해도 페널티 없음
- **스트레이트 유효**: `1-2-3-4-5`, `2-3-4-5-6`, `12-13-14-15-1`(max 15), `10-11-12-13-1`(max 13), `6-7-8-9-1`(max 9), `3-4-5-6-7`
- **스트레이트 무효**: `13-14-15-1-2`, `14-15-1-2-3`, `7-8-9-1-2`(max 9), `1-2-4-5-6`, `11-12-13-14-1`(max 15. 1은 최고 숫자 바로 뒤에만 붙음)
- **강도 순서**(max 15): `1-2-3-4-5` > `2-3-4-5-6` > `12-13-14-15-1` > `11-12-13-14-15` > `3-4-5-6-7`
- **3인 강도 순서**(max 9): `2-3-4-5-6` > `6-7-8-9-1` > `5-6-7-8-9`
- **동률**: 같은 숫자 구성이면 가장 강한 타일 문양이 높은 쪽이 이김(`2-3-4-5-6`은 2의 문양 기준)
- **문양보다 서열 우선**: 백호 2가 들어간 `1-2-3-4-5`가 주작 2가 들어간 `2-3-4-5-6`을 이김
- **스트레이트 플러시**: 주작 `1-2-3-4-5`가 최강. 같은 규칙으로 순서가 매겨짐
- **나머지 조합**: 2 페어 > 1 페어, 2 트리플 풀하우스 > 1 트리플 풀하우스, 2가 가장 높은 플러시 > 1이 가장 높은 플러시

## 6. server 설계 (`apps/server`)
- **코드 변경 없음.** `GameEngine.startRound()`가 매 라운드 `findFirstPlayer`를 호출하므로 R3은 game-logic 변경만으로 반영됩니다. 페널티와 판정도 game-logic을 거칩니다.
- 검증: `tsc` 빌드 통과. e2e 봇 테스트(`apps/server/test/e2e_bot_test.ts`)는 룰 가정이 없어 회귀 확인용으로 실행합니다.

## 7. web 설계 (`apps/web`)

### 7.1 타일 (`components/tile/Tile.tsx`, `tileAssets.ts`)
- 현재 `main`의 타일 디자인은 커밋 `b93b1be`에서 개편되었습니다. 설계문서가 있는 worktree에는 이 커밋이 없으므로 구현·통합 시 최신 타일 코드를 기준으로 진행합니다.
- `tileAssets.ts`에는 이미 로컬 `TOP_NUMBER = 2`와 `isTopTile`이 있습니다. 로컬 상수는 제거하고 `@fgg/game-logic`의 `TOP_NUMBER`를 사용합니다. 기존 `is-top` 클래스와 최강 타일 디자인을 유지합니다.
- `SUIT_META`의 이름·에셋 key·숫자 색상을 사신수 기준으로 함께 옮깁니다: `sun → 주작/jujak`, `moon → 청룡/cheongryong`, `star → 현무/hyunmu`, `cloud → 백호/baekho`. 기존 사신수 그림과 각 사신수의 숫자 색상을 재사용합니다.

### 7.2 공통 로직을 통한 자동 반영
- `ActionBar.tsx`(즉시 검증), `PlayerHand.tsx`(정렬), `lib/suggestions.ts`(추천)의 조합 판정·숫자 정렬은 game-logic의 `detectCombination`·`NUMBER_RANK`를 쓰므로 자동으로 반영됩니다. 최고 숫자 설정은 7.6대로 별도 보정합니다.
- 이 중 숫자 1·2를 하드코딩한 곳이 있으면 수정합니다.

### 7.3 테이블 중앙 안내 (`components/game/CenterField.tsx`)
- 문제: `lastPlay`가 없을 때 항상 "청룡2 보유자가 시작"이 뜹니다. 서버는 라운드 중 전원 패스 시에도 `lastPlay`를 null로 되돌리므로, 새 선 상황에서도 이 안내가 잘못 표시됩니다.
- 변경:
  - 라운드에서 아직 아무도 패를 내지 않았을 때: "**백호 3 보유자가 시작**"
  - 라운드 도중 새 선일 때: "**새 선 — 원하는 조합으로 시작**"
- 두 상황을 구분하는 방법은 구현자가 정합니다. 예: 상위(`GameBoard`)에서 "이번 라운드에 낸 패가 있는지"를 prop으로 전달. 재접속·새로고침 시에도 구분이 유지되는지 검증합니다. 서버 이벤트/상태 스펙은 바꾸지 않는 방향을 우선합니다.

### 7.4 점수판 (`components/game/ScoreBoard.tsx`)
- 페널티 섹션 주석과 하단 안내 문구의 "숫자 1"을 "숫자 2"로 바꿉니다. 배율 설명(2개 ×4, 3개 ×8)은 유지합니다.

### 7.5 mock (`lib/mockGame.ts`)
- `/test/[count]` 화면용 mock입니다. `firstPlayerId: 'p0'`와 일관되게 p0 손패에 **백호 3(`cloud-3`)**을 넣습니다.
- 다른 플레이어 손패에 백호 3이 없도록 정리합니다.
- 바뀐 서열을 보여줄 수 있게 2와 1을 일부 포함합니다.

### 7.6 full 모드의 최고 숫자
- 현재 `lib/suggestions.ts`의 `getMaxNumber`는 인원수만 보고 3인=9, 4인=13으로 결정합니다. `ActionBar.tsx`의 추천과 즉시 검증도 이 값을 쓰므로 full 모드의 서버 판정과 어긋날 수 있습니다.
- 방의 `mode`와 라운드에 적용되는 인원 설정을 공통 `getGameConfig`에 전달해 최고 숫자를 결정하고, 추천과 즉시 검증에 같은 값을 사용합니다. full 모드는 인원과 관계없이 15입니다.
- 기본 3·4·5인과 full 3·4·5인에서 최고 숫자 뒤에 1이 붙는 스트레이트를 검증합니다. 라운드 도중 인원이 줄어도 해당 라운드의 설정을 잘못 바꾸지 않는지 확인합니다.

## 8. 가이드 화면 콘텐츠 요구사항

사용자가 특히 강조한 부분입니다. 세 화면이 **같은 룰을 같은 표현으로** 설명해야 합니다.

### 8.0 공통 원칙
- **G1**: 화면에 보이는 모든 예시 타일 조합은 실제 `detectCombination`으로 판정했을 때 설명과 같은 결과(유효/무효, 종류, 강약)가 나와야 합니다. 구현자는 예시 데이터를 game-logic으로 판정하는 일회성 검증 스크립트를 작업 폴더의 `./tmp/`에 만들어 확인하고, 결과를 보고합니다.
